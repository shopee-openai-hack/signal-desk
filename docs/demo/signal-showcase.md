# 可選社群訊號 showcase

Owner: D

Status: Ready for implementation

Last updated: 2026-09-12

`contracts/fixtures/demo/signals.json` 的 100 系列項目用來擴充輸入案例，不改變
Stage 1–6 的限時 presentation 主線。所有項目都是模擬 Threads 貼文，沿用核心 fixture
的 flat source shape。它們是輸入案例，不是寫死的抽取或案件判斷答案。

## 每則貼文展示的處理邊界

| Stage | Source | 訊號型態 | 預期處理邊界 |
|---|---|---|---|
| 101 | `post_showcase_001` | 同一貼文混合個人經驗、二手解釋、安全疑慮與提問 | 只依可獨立處理的 claim kind 拆分；不可把異味當成污染證據。保留新北範圍與未知批號。 |
| 102 | `post_showcase_002` | Stage 101 的純轉傳 | 保存為相連的 Signal，不建立新 Claim，也不增加獨立證據強度。 |

| 104 | `post_showcase_004` | 相同批號，但味道與外觀正常 | 保留這則經驗。它與先前的感官回報衝突，但「沒有感官異常」和化學危害是不同命題，不能用來反駁化學風險。 |

## 適合在 demo 或 evaluation 呈現的矛盾組合

- Stages 101 與 104 在個人經驗層次看似矛盾，但兩則感官回報都不能判定批次是否有
  化學危害。
- Stages 103 與 105 對 `315-1150404` 的上游與回收範圍提出直接衝突的說法；在權威
  證據解決衝突前，兩邊都必須可見。
- Stages 107 與 110 往相反方向過度泛化。系統應把每個 Claim 縮到證據支持的品牌、
  商品與批號範圍。

可選 track 的完成條件：ingestion 能載入指定的 100 系列 stage、repost 保留明確連結、
抽取結果保留原文 quote 與未知範圍，且案件層能記錄互相矛盾的 Claims 而不覆寫任一來源。
UI 可用獨立 showcase filter 呈現，但預設不可把額外項目混入限時六段 presentation。
