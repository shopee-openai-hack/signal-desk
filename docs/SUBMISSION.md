# Signal Desk — 提交概覽

更新：2026-09-12。狀態：提交準備中，尚未宣告正式提交或完整產品驗收。

## 產品說明

Signal Desk 協助商品安全營運人員把分散的市場通報整理成可追溯案件，閱讀證據與未知事項、確認候選商品，並在人員核可後執行商品處置。新證據可改變優先級或縮小影響範圍，過往判斷及操作仍保留。

## 目前可展示

- 市場通報：來源、陳述、查核證據及案件關聯。
- 案件列表與詳情：影響、優先級、負責者、商品關聯、追蹤計畫；案件時間軸由新到舊。
- 商品核可與執行：明確分開選取、核可和執行，保存逐項結果，支援失敗重試。
- 案件歷程回放：垂直階段與子活動、輸入輸出、來源和前後差異；底部播放器可逐步閱讀。

## 展示架構與限制

瀏覽器 → 同源 FastAPI `/api/v1/demo/*` → 保存的案例快照與 SQLite 商品／核可／執行狀態。前端不需要獨立 Node mock server。回放使用 `contracts/fixtures/demo/backend_replay.json`；不是現場模型推論。

即時訊號匯入、查核與案件處理 API 位於 `/api/v1/*`，與受控展示分離。即時流程到四頁 UI、即時 Trace producer 及 live 商品執行不是本次受控展示已證明的能力。加入 OPENAI_API_KEY 不會自動切換 UI 的資料來源。

商品與賣家是示範資料，未連接真實平台；外部公告、新聞及模擬批號映射見 [Demo pack](demo/demo-pack.md)。不宣稱即時監控、真實平台下架或模型私有推理可見。

## 建議展示順序

1. 從預設案件進入，說明獨立回報、批號與仍待確認的部分。
2. 展開「展示設定」推進官方證據，再回到商品清單。
3. 確認三筆商品、核可並執行；重新整理，確認下架結果仍在。
4. 揭露新候選與放行證據，說明新商品不繼承舊核可、既有下架不自動恢復。
5. 開啟案件歷程回放，展開一個複雜階段，展示證據、活動和前後差異。

完整技術步驟見 [Frontend](../frontend/README.md)，原六分鐘旁白見 [Demo script](demo/demo-script.md)。影片 task 的產出需另確認並連回此文件，不把工作中影片當成提交附件。
