# INTENT — 員工前端、情境回放與互動 mock

Status: Accepted（本次對話已確認範圍；未決細節見 Open Questions）
Owner: C — Frontend workstream
Last updated: 2026-09-12

## Summary

員工需要從分散的市場訊號理解案件、證據與商品關聯，再確認指定模擬商品的下架；評審需要逐步看懂案件如何因新證據改變，而非只看到最後結果。前端以四個頁面支援日常檢視與情境回放，並在後端並行開發期間提供可互動的 mock，讓操作流程能獨立被檢視與驗證。

本文件只定義前端功能意圖。[根目錄 INTENT](../INTENT.md) 仍是整體產品範圍的權威；本文件不得擴張真實平台操作授權。下列 `INT-*` ID 以本文件路徑為命名範圍，跨文件引用時須包含路徑，避免與根目錄 ID 混淆。

## Problem

- 單看案件最新狀態，員工與評審無法理解輸入、處理、判斷變化及人工介入之間的關係。
- 若候選商品、已核可對象與實際執行結果混在一起，容易誤解商品已被證實有問題或已完成下架。
- 案件由專員承接不代表專員正在執行；缺少狀態資訊時，使用者無法分辨處理中、等待與失敗。
- 前後端同時開發，若前端必須等待所有後端能力完成，團隊就無法提早驗證互動與展示敘事。

## Affected Users / Systems

- 內部營運人員：首版採單一操作角色，檢視案件並核可模擬商品下架。
- 展示者與評審：播放已保存的情境，理解完整流程、適應行為及例外處理。
- 前後端開發者：在共用資料語意下並行開發與整合。

## Desired Outcomes

- **INT-G1** — 員工能從訊號找到關聯案件，理解其業務影響、優先級、負責者與當前狀態。
- **INT-G2** — 員工能分辨陳述查核結果、商品候選關聯及缺失資訊，依據證據評估下一步。
- **INT-G3** — 員工能確認指定模擬商品，分別辨識核可與執行結果，重新查看時仍能追溯操作及商品狀態。
- **INT-G4** — 評審能重複觀看已保存的流程，理解各步驟的輸入、結果、處理理由及案件前後變化。
- **INT-G5** — 使用者能知道專員目前在做什麼、為何等待、最近結果及下一次預定動作。
- **INT-G6** — 後端尚未完成時，團隊仍能操作四頁與關鍵成功、等待、失敗情境；接入後端後維持一致的使用者理解與操作流程。

## Scope

### 四個主要頁面

| 頁面 | 使用者可完成的事 |
| --- | --- |
| 訊號收件匣 | 檢視原始內容、來源與時間、訊號類型、重複或獨立來源標記，以及關聯案件；首版以檢視為主。 |
| 案件列表 | 比較業務影響、優先級與理由、案件狀態、承接專員、最新變化與下次追蹤；作為日常首頁。 |
| 案件詳情 | 理解證據與未知事項、檢視相關商品、確認並執行模擬下架，以及追溯案件歷史。 |
| Trace／情境回放 | 選擇情境並觀看跨訊號、分派、查核、案件更新、人工核可及執行的過程；作為展示入口。 |

案件詳情包含三個分頁：「案件概覽」呈現判斷、陳述、證據、未知事項、下一步與追蹤計畫；「相關商品」呈現關聯依據、缺失資訊、商品狀態與下架操作；「案件時間軸」保留歷次證據、判斷、核可及執行紀錄。

### 核可與執行

員工先勾選商品並確認核可，再明確執行模擬下架。畫面區分已核可但尚未執行、成功與失敗，並呈現逐項結果。核可後若案件版本改變，舊核可須阻擋執行，要求依最新案件重新確認。新增商品不沿用既有核可。

### Trace 與情境回放

- 必要交付是播放預先跑好並保存的紀錄，提供播放、暫停、前後跳步與速度調整。
- 以有意義的業務步驟呈現當時輸入、結果、證據支持的摘要、負責角色與狀態；可查看案件前後差異。技術細節可展開，但不成為閱讀主線。
- 以垂直時間軸保留已播放階段；目前階段可展開 Agent 的可觀測活動，例如搜尋、讀取來源、工具呼叫、交接與重試。複雜階段須能分辨已完成與尚未播放的活動，並在階段摘要、活動結果與原始細節之間逐層閱讀。
- 觀看者可逐個活動或跳至下一階段，追蹤當時判斷、證據及影響範圍的改變。歷史節點在播放後仍可展開，未播放資訊不得被誤認為當時已知；人工回看時不強制捲回播放位置。
- 案件時間軸服務單一案件的業務追溯；Trace 服務一次流程的跨角色檢視。相關案件、來源、證據、核可及執行紀錄可互相追溯。
- 回放遇到人工核可階段暫停，讓觀看者理解介入點；繼續播放只展示既有核可紀錄，不產生新核可或執行。
- 情境以一條食用油完整主線為主，並涵蓋初始證據不足、重複轉傳、新品牌或批次、確認或反駁證據，以及執行失敗與重試。合成例外情境須明確標示。
- 「按下一步現場觸發下一段流程」是後續加分能力，不是首版回放驗收前提。若提供，應建立獨立的新執行，顯示實際等待及失敗，到核可階段由員工真的確認；不同執行的模擬商品狀態相互隔離。

### 專員狀態

案件列表顯示精簡狀態，案件詳情嵌入完整專員面板，Trace 顯示步驟負責角色。使用者能辨識待處理、執行中、等待人工、等待追蹤及失敗，並看到目前步驟、最近結果、等待原因、下一次動作及相關執行紀錄。邏輯角色不代表獨立常駐程序。

### 可互動 mock 與展示偏好

- 在後端未完成時，mock 支援跨頁檢視、商品勾選、核可、執行、狀態保留、回放及例外情境，不限於靜態假資料或成功提示。
- mock 使用與中央合約一致的資料語意；前端不另行發明案件判斷規則。尚未提供的能力與資料缺口須可辨識。
- mock 操作後重新整理仍可驗證該情境的商品與執行狀態；可明確重置模擬情境再演示，不影響已保存的回放紀錄或其他執行。
- mock、已存紀錄回放與現場執行需清楚區分。真實執行失敗時不得悄悄以 mock 成功取代。
- 首版以繁體中文、桌面操作與投影可讀性為設計偏好；情境輸入集中於回放入口，訊號收件匣不另建一般手動匯入流程。

## Non-goals

- **INT-NG1** — 首版不另建總覽 Dashboard、商品管理、核可中心或 Agent 管理頁，不擴張為通用營運後台。
- **INT-NG2** — 不在前端重做案件分派、證據判定或優先級決策，也不將 mock 判斷當作後端能力證明。
- **INT-NG3** — 不操作真實平台商品，不新增多角色權限管理、主動通知或通用 Agent 控制台。
- **INT-NG4** — 首版不以現場逐步執行、全天候即時監測或通用技術追蹤分析平台作為必要交付。

## Constraints

- **INT-C1** — 沿用既定技術與部署邊界，以及根目錄 INTENT 中的證據、模擬商品、人工核可與歷史保留要求。
- **INT-C2** — 業務影響、調查優先級、陳述查核結果與商品關聯分開呈現；未知或候選不能被顯示成已證實。
- **INT-C3** — 下架只作用於當次選定且有效核可的模擬商品；失敗不能顯示成功，重複執行不得產生重複操作。
- **INT-C4** — 回放使用當時紀錄與狀態，不以最新案件覆蓋歷史；播放或跳步不觸發 API 費用、核可或商品狀態變更。
- **INT-C5** — mock、合成情境、已保存的實際紀錄與現場執行必須可辨識；mock 成功不代表後端整合或雲端驗證完成。
- **INT-C6** — 專員狀態須反映可觀測的執行或回放事件；未提供狀態時表達未知，不因承接案件而虛構運行中。
- **INT-C7** — Trace 呈現證據支持的決策摘要，不展示模型私有推理、金鑰或其他秘密。

## Assumptions

- **INT-A1** — 單一內部營運角色、繁體中文桌面介面足以驗證本次核心操作與展示需求，尚未經實際使用者測試。
- **INT-A2** — 後端工作流可提供足以連結案件、來源、核可與執行的紀錄；完整 Trace 與專員狀態目前仍需協調。
- **INT-A3** — 已保存紀錄能降低展示對現場服務的依賴；仍需取得完整且可重播的代表性紀錄。

## Open Questions

- **INT-Q1** — 食用油案例的具體歷史事件、來源、模擬品牌與批次、六分鐘腳本及樣本負責人仍待整體團隊確認；不預設真實品牌責任。
- **INT-Q2** — A／B／C 如何分工提供收件匣、完整陳述與證據、Trace、專員狀態及核可／執行結果？中央合約尚未完整涵蓋這些資料，後續規格需對齊。
- **INT-Q3** — 真實失敗與重試的具體語意、案件版本改變造成核可失效的跨工作流處理，需依此意圖在中央合約中落實。
- **INT-Q4** — 現場逐步執行是否納入本次加分交付，留待基本回放可用後決定；不阻擋四頁與 mock 的意圖。

## Success Signals

- **INT-S1** — 員工可從訊號進入案件，指出業務影響、優先級理由、陳述證據、商品關聯及尚未確認的部分。（INT-G1/G2、INT-C2）
- **INT-S2** — 在互動 mock 中完成選取、核可及執行後，重新整理仍顯示相同結果；未選取與新加入的商品維持原狀。（INT-G3/G6、INT-C3/C5）
- **INT-S3** — 核可後案件版本改變會阻擋舊核可執行；失敗可見，重試不重複執行，核可與執行紀錄可追溯。（INT-G3、INT-C3）
- **INT-S4** — 評審可播放、暫停及跳回先前步驟，看到當時狀態並說明新證據如何改變案件；觀看不改變商品或核可紀錄。（INT-G4、INT-C4）
- **INT-S7** — 評審能在同一垂直時間軸展開複雜階段，指出 Agent 取得哪些輸入、執行哪些可觀測活動、遇到何種失敗或重試、產出哪些結果，以及結果如何改變案件判斷；無須靠內部識別碼或模型私有推理理解流程。（INT-G4/G5、INT-C4/C7）
- **INT-S5** — 使用者能分辨案件調查中但專員等待、專員實際執行中與執行失敗，並找到原因及下一步。（INT-G5、INT-C6）
- **INT-S6** — 後端未啟用時四頁仍可互動並展示例外情境；觀看者能正確指出目前資料模式。後端整合完成另以實際執行與持久化證據驗收。（INT-G6、INT-C5）

## Context / Learnings

- 本次對話確認四頁、嵌入式專員狀態、預先保存紀錄回放優先，以及逐步現場執行作為加分項目。
- 使用者接受案件列表作為日常首頁、回放作為展示入口、核可與執行分步、版本改變後重新核可，以及桌面繁中與投影可讀性方向。
- 本文件完成不代表 mock、前端、Trace 或後端已實作；中央合約與相關工作項目仍需在後續規格階段對齊。
